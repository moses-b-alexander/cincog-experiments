How the divergence was computed
        
In the comparison JSON, P is C’s vector after base and Q is its vector after bsln. The active rule was hidden in both requests. Align the same 64 words and set M = (P + Q) / 2.

        
JS(P,Q) = ½ Σ P(w) log₂[P(w)/M(w)] + ½ Σ Q(w) log₂[Q(w)/M(w)]

        
TV(P,Q) = ½ Σ |P(w) − Q(w)|

        
Zero-weight terms contribute zero. No smoothing is used. Vectors are divided by their totals only to remove floating-point sum error. All calculations use unrounded values, including words omitted from the small chart.

A vector is not a frequency estimate.
These are native System One action probabilities from two saved requests. The host took the highest-weight action once in each condition. The two recorded responses do not estimate frequencies across repeated runs.
The native reply also reports a separate confidence field. It is not the chosen word’s probability. Conventional next-token scores conditioned on offered codes measure something different and are not combined with this comparison.

Provenance and what remains unresolved
  • C4 is one fixed sender choice with two fresh receiver conditions. It is not a population estimate or a test of multi-turn learning.
  • A strategic B, new prompts, menu order, bank membership and new downstream histories require new model requests.
  • The registered trace records the Kev model tag and workflow digest, but no exact weight digest or server identity. Saved-record replay is exact; fresh inference equivalence is unqualified.
  • Large menus, different hardware and Linux parity remain unqualified.
  • The release provides source for inspection and reproduction. It does not add a new software license grant.
